Tech choices · Why no framework

本项目有意不引入 React、Vue、Dify、LangChain 等框架——这是有意识的工程决策，不是不会用。理由：

✅ What I chose

Single-file HTML (110 KB)
所有 CSS / JS / SVG / 图标内联。零外部资源，离线可用，可邮件分发，可直接打印。
PyWebView as desktop shell
同一份渲染层在浏览器和桌面运行，零重复开发。WebView2 在 Windows 10/11 自带。
Python + requests for RSS
5 个 RSS 源、关键词打分、配额裁剪、日期时效性加权——纯标准库逻辑，无爬虫框架。
Windows Task Scheduler
系统原生调度，零额外进程；不引 Airflow / Celery 这类重组件。
Atomic write with os.replace
临时文件 → 原子替换，意外断电数据不损坏；不引 SQLite / LevelDB。

❌ What I didn't add (and why)

×
No React / Vue / Tailwind
单文件 110KB 装得下全部交互；引入框架后构建产物 ≥ 500KB，破坏「零依赖」目标。
×
No Dify / Coze / LangChain
本项目没有 LLM 调用链（资讯抓取是 RSS，非生成）。框架会引入无意义的复杂度。
×
No Electron / Tauri
Electron 打包 ≥ 80MB；PyWebView 直接复用 Windows WebView2，14MB 足够。
×
No SQLite / Peewee
localStorage（网页版）+ JSON 文件（桌面版）足够 5 个模块的数据量；引 DB 反而拖慢迭代。
×
No CDN / External font / Chart lib
图表全用内联 SVG 手写。断网时也 100% 可用，对作品集 demo 是关键加分项。
